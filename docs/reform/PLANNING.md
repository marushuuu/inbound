# リフォーム向けプロダクト 企画・要件定義ドキュメント(初版)

対象スコープ: **現場調査 〜 契約** までの業務のプロダクト化。
このドキュメントは「これから共有いただきたい情報の整理」と「構築の進め方の提案」をまとめたものです。
共有いただいた情報をもとに随時更新していきます。

---

## 1. 共有いただきたい情報

### 1-1. ビジネスの前提(最優先)

| # | 項目 | 知りたいこと |
| --- | --- | --- |
| 1 | 利用者 | 自社(1社)の業務ツールか、リフォーム会社向けに販売するSaaSか。使う人は誰か(営業、調査員、積算担当、経営者)。 |
| 2 | 対象工事 | 水回り(キッチン・浴室・トイレ)、内装、外装・屋根、外構、フルリノベなど、どの工事種別が中心か。 |
| 3 | 案件規模 | 月間の問い合わせ数・調査件数・成約数、平均単価、成約率。ボトルネックはどの工程か。 |
| 4 | 現在のやり方 | 今は何を使っているか(紙の調査票、Excel見積、既存システム等)。何に一番困っているか。 |
| 5 | 体制 | 調査に行く人と見積を作る人は同じか別か。承認フロー(上長チェック等)はあるか。 |

### 1-2. 業務フローの実物資料

実際に使っている帳票・資料をそのまま(サンプルで可)共有いただけると、データモデルと画面設計が一気に具体化します。

- **現場調査票**: 調査時に何を記録しているか(部位ごとのチェック項目、採寸箇所、劣化状況、写真の撮り方・枚数)
- **見積書のサンプル**: 明細の構造(工事項目 → 部材・数量・単価・歩掛かり)、値引き・諸経費の扱い
- **単価表 / 商品マスタ**: 標準工事単価、よく使うメーカー設備(型番・仕入価格・定価)
- **提案書のサンプル**: 顧客に見せる資料の構成(プラン図、施工イメージ、工程表など)
- **契約書式**: 工事請負契約書、約款、クーリングオフ告知書面など現在使っているもの

### 1-3. 業務ルール・法規制まわり

- 契約は**電子契約**にしたいか、紙(印刷して押印)のままか
- 訪問販売に該当する営業形態か(特定商取引法のクーリングオフ書面要件に関わる)
- 建設業許可の有無・リフォーム瑕疵保険の利用有無
- 見積の有効期限、追加工事・変更契約の扱い

### 1-4. 技術・運用の制約

- 現場で使うデバイス(スマホ / タブレット / 紙+後入力)
- 現場の電波状況(オフライン入力が必要か)
- 予算感とリリース希望時期
- 既存の顧客リスト・過去案件データの移行が必要か

> **すべて揃わなくてもOK**: 最低限 1-1 と「現場調査票+見積書サンプル」があればMVP設計に着手できます。

## 2. プロダクト構築の進め方(提案)

### 2-1. 対象業務フロー

```
問い合わせ → 案件登録 → 現場調査(採寸・写真・ヒアリング)
→ プラン・見積作成 → 提案 → (再調査・再見積) → 契約締結
```

契約以降(着工・工程管理・引き渡し)は当面スコープ外とし、拡張余地として設計だけ考慮します。

### 2-2. フェーズ分け

| フェーズ | 内容 | 成果物 |
| --- | --- | --- |
| Phase 0 | 要件定義: 業務フロー図・画面一覧・データモデル確定 | このドキュメントの完成版 |
| Phase 1 | **案件管理 + 現場調査**: 顧客・案件の登録、スマホでの調査記録(部位別チェック・採寸・写真・メモ) | 動くMVP(まずサンプルデータのフロントエンド → その後DB接続) |
| Phase 2 | **見積作成**: 単価マスタ・商品マスタ、明細組み立て、見積書PDF出力、社内承認 | 見積機能 |
| Phase 3 | **提案〜契約**: 提案書生成、見積の版管理(再見積)、契約書出力 or 電子契約連携、ダッシュボード(案件ステータス・成約率) | 契約までの一気通貫 |

各フェーズの終わりに実際の案件で試していただき、フィードバックを次フェーズに反映します。

### 2-3. 想定データモデル(たたき台)

- **顧客** (Customer): 氏名、連絡先、住所、流入経路
- **案件** (Project): 顧客、物件情報(築年数・構造)、工事種別、ステータス(問い合わせ/調査済/見積提出/契約/失注)
- **現場調査** (Survey): 案件に紐づく調査記録。部屋・部位ごとの採寸値、劣化状況、写真(位置タグ付き)、ヒアリングメモ
- **見積** (Estimate): 案件に紐づく。版番号を持ち再見積に対応。明細(工事項目 × 数量 × 単価)、諸経費、値引き
- **マスタ**: 工事項目・標準単価、商品(メーカー設備)
- **契約** (Contract): 確定見積への参照、契約日、書面、ステータス

※ 1-2 の実物資料を反映して確定させます。

### 2-4. 技術方針

- 本リポジトリと同じ **Next.js (App Router, TypeScript) + Tailwind CSS** で構築
- 現場調査はスマホ利用が前提のため**モバイルファースト**で設計(必要ならPWA化・オフライン対応を検討)
- DB・認証・写真ストレージはPhase 1後半で導入(Supabase / PostgreSQL 等を想定、要件確定後に選定)
- 見積書・契約書はPDF生成。電子契約は外部サービス連携(クラウドサイン等)を検討
