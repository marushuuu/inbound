# 業界ナレッジから導いたプロダクト更新方針(v0.5 → v1.0 に向けて)

- 作成日: 2026-09-01
- 入力資料: `260820_業界知識_リフォーム_川鍋 v1.0`(以下「ナレッジ」)、および既存の `reformworkflowtrainingdata.md`
- 対象プロダクト: `reform-app/`(現場調査〜契約のリフォーム営業SaaS、現行 v0.5)

> **取扱注意**: 入力資料には社外秘情報(クライアント個社名・実数値、ANDPAD横断のLooker実測値、担当者グレード要件のサンプル)が含まれます。本ドキュメントには**個社名と社外秘の実測値は転記していません**。プロダクト設計上の構造・論理と、参照可能な数値のみを記載しています。原典を参照する際は匿名化ルールに従ってください。

## 0. 結論(3行)

1. 現行プロダクトは「**見積を速く作る**」までは押さえているが、ナレッジが最重要と位置づける「**粗利を守る**」の機能が丸ごと無い。見積に原価・粗利の概念が存在しないのが最大のギャップ。
2. ナレッジの消費者調査は「**現調後失注の67%は価格以外＝改善可能**」「**初動3日**が分水嶺」「**問い合わせ社数は7割が1社のみ**」と示す。つまり勝負は "安さ" ではなく **速さ・提案・態度の標準化**。ここはプロダクトで直接支援できる。
3. ナレッジのAI検討の本命 **「F 類似案件サジェスト = 粗利毀損のない見積雛形を作成者名付きで提示」** は、現行の「類似の過去見積検索」の**正常進化形**。今の実装はメタデータ類似止まりなので、明細レベル＋粗利実績付きに引き上げるのが最短の差別化。

## 2. 優先度つきバックログ

優先度は「**受注時粗利の防衛 > 失注の削減 > 単価アップ > 可視化**」の順。これはナレッジのKGIが「利益改善」であり、ボトルネックが「粗利の毀損」と「案件回転のスピード」だとされていることに従っています。

### P0 — 次に実装すべき(粗利を守る)

#### P0-1. 見積に原価・粗利を持たせる ★最重要

ナレッジの中心概念(§3「粗利は2回減る」)がプロダクトに存在しないことが最大の欠落。

- `WorkItem` に **標準原価**(材工の原価、または人工単価×所要時間)を追加
- `Product` に **仕入額**(`costPrice`)を追加。定価(`price`)と別に持つ
- `EstimateLine` に原価列を追加し、`calc.ts` で **受注時粗利額・粗利率** を算出
- 見積画面の合計欄に「**粗利率 34.2%**」を常時表示。目標(契約時34〜35%)を下回ると警告色
- 松竹梅の切り替え・設備グレードの差し替えで粗利率がリアルタイムに動くようにする

> 効果: 営業がその場で「この値引きをすると粗利が31%になる」と分かる。ナレッジの「自分の見積が会社の利益を決める」を画面で体現する機能。

#### P0-2. 現調その場で出す「概算見積」モード

ナレッジは、ハイプレイヤーが現調時に仮見積を出せる理由を「**材料単価は概ね分かる／人工と材料費が概ねイコールになる方式で概算できる**」と具体的に書いている(§7-4)。この計算方式をそのまま機能にできる。

- ヒアリング画面から「**概算を出す**」→ 工事パターン(トイレ交換/UB交換/洗面+クロス 等)を選ぶだけで概算レンジを提示
- 計算根拠は既存の工事マスタ(`durationMinutes` × 人工単価 + 材料費)。所要時間はすでに分単位で持っているので、**人工単価を追加するだけで成立する**
- 出力は「**¥○○万 〜 ¥○○万(概算・現地確認により変動)**」のレンジ。確定見積との違いを明示
- 等級別リードタイム目標(30万以下は現調時その場、〜100万は3日 等)を目安として画面に表示

> 効果: ナレッジの育成論(等級3-1以上に求められるスキル)を、経験の浅い営業でも道具で代替できるようにする。育成に4〜5年かかるという構造課題への直接的な回答。

#### P0-3. 失注理由の型化

ナレッジ §10-2 の BEFORE/AFTER 表がそのまま仕様になる。実装コストが小さいわりに、後段の分析価値が最も高い。

- 案件を失注にする際、以下を**必須入力**にする
  - 区分: `他決` / `検討中止`
  - 理由: `価格` / `時期` / `プラン` / `その他(備考必須)`
  - 他決の場合は**競合先**を記録
- 案件一覧に失注理由でのフィルタを追加

#### P0-4. フェーズ別リードタイムの自動計測

- `Project` に `inquiredAt`(反響日) / `surveyedAt`(現調日) / `quotedAt`(見積提出日) / `contractedAt`(既存) を持たせ、**画面遷移で自動打刻**する(手入力させない)
- 案件一覧に「見積待ち 4日」のような経過日数バッジ
- **初動3日ルール**: 反響から接触まで3日を超えた案件を警告表示(§5-6 の「反応まで3日以上が60%」に対応)

#### P0-5. 見積の有効期限と資材高騰条項

資材が20〜40%高騰し、契約済み顧客への値上げ分を自社が被るリスクが顕在化している(§1-2)。これは法務リスクでもある。

- 見積書に **有効期限**(既定30日など)を印字
- 変動リスクメモに「**メーカー価格改定・納期遅延**」のテンプレ文を用意(現状は自由記述のみ)

### P1 — その次(失注を減らす・単価を上げる)

#### P1-1. 類似案件サジェストの明細レベル化 ★ナレッジの本命候補

ナレッジ §13-4 が現時点の本命として挙げる「F 類似案件サジェスト = 見積明細をコード化し、**粗利毀損のない見積雛形を作成者名付きで提示**」。現行の類似検索(工事種別+3/築年数帯+2/予算+2/構造+1 のルールベース)は入口としては正しいが、返しているのが**要約情報だけ**で明細が無い。

- 過去見積を**明細ごと**保持し、「この見積をベースに作成」で**明細が丸ごと入る**ようにする
- 各候補に **作成者名** と **その案件の完工粗利率** を併記(＝粗利が守れた見積だけを手本にする)
- 粗利率が目標を下回った案件は「参考(粗利毀損あり)」として区別
- 将来的にはルールベース → ベクトル類似(pgvector)へ

#### P1-2. 拾い漏れチェックリスト(工種 × 注意点)

ナレッジ §3-3・§4-4 の「B. ナレッジ・コンテンツ(工種×注意点ナレッジ)」の実装形。

- 工事種別ごとに「見落としやすい項目」をマスタ化(例: UB交換 → 給湯器の能力確認、電気容量、搬入経路、ダブルトラップ)
- 見積確定前に**チェックゲート**として提示。未チェックがあると警告
- §11 のトラブル事例②(ダブルトラップで引き渡し後クレーム → 追加工事の費用を払ってもらえない)が、まさにこのチェックで防げる類の事故

#### P1-3. 追加提案(+α)サジェスト

**18%が当初予定外の工事・グレードアップを実施している**(§5-7)。ここは単価アップの実証済みの余地。

- ヒアリングで入力した**築年数・リフォーム履歴**から「**2〜3年後に必要になる可能性**」を提示(§7-4 のできる営業の条件をシステム化)
- 工事種別ごとの**複合セット提案**(トイレ・風呂は半分が複合需要)
- 見積画面に「よく一緒に提案される工事」を候補表示

#### P1-4. 顧客提示用の提案ビュー(工事イメージシート)

選定理由の1位が**工事内容の提案の良さ**(§5-5)。一方で興味どまりの45%が「営業をかけられそう」という心配(§5-4)。つまり**押しの営業ではなく、分かりやすい提示**が効く。

- 見積とは別に、顧客に見せる**タブレット提示モード**(施工事例写真・工事の流れ・概算工程表・松竹梅の比較)
- 現状の商品カタログを「グレード比較」として提示画面に組み込む

#### P1-5. 商品マスタの仕入先別価格

**同じ商品でも商社によって仕入額が違う**(§3-4)。P0-1 の粗利計算の精度は、ここに依存する。

- `Product` に仕入先ごとの仕入額を複数持てるようにし、最安を既定にする
- カタログ取込(§8 で検討済みの半自動取込)と合わせて設計

### P2 — SaaS として売るために(管理者・経営者向け)

現行は営業担当の単一ロールしか想定していない。ナレッジ §14-2 の「現場 / 管理者 / 経営層」の3レイヤーのうち、**上2つが空白**。

- **P2-1. KPIダッシュボード**: 反響数 / 契約率(価格帯別・反響元別) / 受注時粗利率 / リードタイム / 失注理由の内訳。ナレッジ §4-1 の10指標のうち、契約までのスコープで取れるものを実装
- **P2-2. 承認の関所(ワークフロー)**: 一定金額以上(導入事例では150万円)や、**粗利率が目標を下回る見積**は上長承認を必須にする。§14-3 のKSFに直結
- **P2-3. 担当者別の生産性ビュー**: 「150万円以上の案件を月1件以上受注できる人材の比率」が生産性の代理指標(§8-3)。担当者ごとの契約率・粗利率・リードタイムを等級目安と並べる
- **P2-4. ANDPAD連携の受け渡し設計**: 完工粗利・入金・リピートは契約後の指標でスコープ外。**契約時点のデータ(見積明細・原価・実行予算の種)をANDPADに渡す**前提で項目を揃えておく

## 3. スコープ外だが接続を意識すべき領域

ナレッジの価値の多くは**契約後**にある(完工粗利、口頭発注、入金管理、リピート率)。現行プロダクトのスコープは契約までなので、以下は「自前で作らず、渡す」方針とする。

| 領域 | ナレッジの指摘 | 本プロダクトの方針 |
| --- | --- | --- |
| 完工粗利の管理 | 粗利の2回目の毀損はここで起きる(§3-2) | 受注時粗利までを正確に作り、ANDPADへ受け渡す |
| 発注・実行予算 | 口頭発注が請求不一致を生む(§11-④) | スコープ外。ANDPAD受発注へ |
| 入金・キャッシュフロー | 小口大量で管理が甘くなる(§10-4) | スコープ外 |
| リピート・OB接点 | 複数回実施者の70%強が同じ会社にリピート(§5-7) | 契約時に「**次回提案メモ**」(2〜3年後の想定)を残す機能だけ持ち、追客はANDPAD/CRMへ |

## 4. 判断を仰ぎたい点

1. **「キーマン(決裁者)」項目の再導入**
   第2次フィードバックで「キーマン同席」項目は不要として削除しました。一方でナレッジは「決裁者はご家族全員で、ご主人・奥様・同居のご両親で意見が違う。キーマンの見極めが要る」(§2)と明確に書いています。削除したのは「同席したか」というチェック項目だったので、**「誰が決裁者か」という別の形**であれば価値がありそうですが、再導入するかは判断をお願いします。

2. **原価データの入手経路**
   P0-1(粗利表示)は、原価が入っていないと成立しません。標準原価を①工事マスタに手入力する、②過去の実行予算から取り込む、③ANDPADから引く、のいずれで始めるかで初期の作り込みが変わります。

3. **概算の計算方式**
   P0-2 は、ナレッジ記載の「人工と材料費が概ねイコールになる方式」を採用すると即座に作れます。この方式でよいか、御社の実態に合う係数があるかを確認したいです。

4. **等級・目標値の扱い**
   ナレッジのグレード要件はサンプル値で、v2(1.30倍更新版)との差分が未確認とされています。プロダクトに目標値(契約時粗利34〜35%、リードタイム基準)を埋め込む場合、**会社ごとに設定可能**にするのが安全だと考えます。

## 5. 推奨する着手順

```
v0.6  P0-1 見積の原価・粗利  +  P0-3 失注理由の型化
        └ 粗利が見える / 失注が分析できる。データが貯まり始める

v0.7  P0-2 概算見積モード  +  P0-4 リードタイム自動計測  +  P0-5 見積有効期限
        └ 「速さ」の勝負に乗る。初動3日・現調その場概算

v0.8  P1-1 類似案件サジェスト(明細+作成者+粗利実績)  +  P1-2 拾い漏れチェック
        └ ナレッジの本命。育成課題への回答

v0.9  P1-3 +α提案  +  P1-4 顧客提示ビュー
        └ 単価アップ(18%の余地)

v1.0  P2 管理者・経営者レイヤー(ダッシュボード / 承認フロー)
        └ SaaSとして「会社に売れる」状態にする
```

P0-1 と P0-3 は、いずれも既存のデータモデルへの追加で済み、画面の作り替えを伴いません。**まず v0.6 の2本から着手するのを推奨します。**
